# Валидация реквизитов ЭПД по требованиям ФНС

Рабочая документация для правил проверки данных в **EDO Adiutor** (список документов + карточка).

## Статус

| Этап | Описание | Статус |
|------|----------|--------|
| 1 | Line-clamp длинных значений в карточке | готово (UI) |
| 2 | Редактирование простых реквизитов из карточки | в работе |
| 3 | Сбор нормативной базы ФНС/XML по типам ЭПД | **начат** (этот каталог) |
| 4 | Проверки в UI (ошибка / спорно / OK / внешний сервис) | запланировано |

## Типы документов 1С (ориентир для разделов)

См. перечень в [document-types.md](./document-types.md).

По каждому типу — отдельный файл:

- [etrn.md](./etrn.md) — электронная транспортная накладная (ЭТрН)
- [ezz.md](./ezz.md) — электронный заказ-заявка (ЭЗЗ)
- [ezzn.md](./ezzn.md) — электронный заказ-наряд
- [epl.md](./epl.md) — электронный путевой лист
- [esv.md](./esv.md) — электронная сопроводительная ведомость
- [edf.md](./edf.md) — электронный договор фрахтования

## Как пользоваться при разработке

1. Для каждого реквизита фиксируем: **XML-путь**, **формат**, **обязательность**, **ссылка на приказ/ XSD**, **уровень проверки** (`error` | `warn` | `external`).
2. Реализация проверок — в коде (отдельный этап); этот каталог — **источник истины** для сообщений и стилей в списке.
3. Спорные случаи помечаем `warn` и кратко описываем, почему автомат не может дать «жёсткий» вердикт.
