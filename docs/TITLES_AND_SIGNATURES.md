# Титулы и подписи ЭПД (справка для UI)

Документ для разработки иконки подписей, колонок таблицы и будущей динамической сетки этапов.

## Источник в 1С (форма обработки)

### Карточка документа (detail JSON)

Функция `МассивДатТитуловЭТН(Документ)` формирует массив `{ key, value }`:

| key (подпись в UI) | Поле документа (ЭТрН) |
|--------------------|------------------------|
| Грузоотправитель | `Документ.ТитулГрузоотправителяДатаФормированияФайла` |
| Перевозчик (приёмка) | `Документ.ТитулПеревозчикаПриемкаДатаФормированияФайла` |
| Грузополучатель | `Документ.ТитулГрузополучателяДатаФормированияФайла` |
| Перевозчик (выдача) | `Документ.ТитулПеревозчикаВыдачаДатаФормированияФайла` |

**ЭТрН:** 4 титула в данных, в списке UI пока **3 слота** на иконке (упрощение).

### Список (list JSON)

Поля, используемые React сейчас:

- `currentStep` — строка текущего шага (часто с номером титула, напр. «T2 …»).
- `currentStepDone` — булево, шаг считается выполненным.
- `posted` — документ проведён (все слоты иконки зелёные).
- `titleDates` — **только в detail**, в list **нет** (эвристика по `currentStep`).

### Соответствие типов документов (эвристика `docSignatureProgress.ts`)

| docType | Слотов на иконке |
|---------|------------------|
| ЭЗЗ / EZZ | 2 |
| ЭТрН / ETRN / содержит «ТрН» | 3 (фактически до 4 титулов в BSL) |
| прочее | 3 по умолчанию |

## Риски сценария «3 колонки × N подписантов»

1. **Колонки таблицы** сейчас жёстко: документ | грузоотправитель | перевозчик | грузополучатель. При других этапах (4-й титул перевозчика, доп. участники) колонок может потребоваться больше трёх.
2. **Иконка** рисует фиксированное `signedSlots.length` (2 или 3). Для ЭТрН корректнее **4 слота** или динамика из `titleDates.length`.
3. **Подпись перевозчика** в BSL дважды (приёмка / выдача) — в эвристике list оба могут схлопываться в один слот.

## Рекомендуемый план (D2)

1. **List JSON:** добавить `titleDates` (тот же массив, что в detail) или компактный `signatureSlots: boolean[]` с сервера.
2. **UI:** `signatureSlotCount` = `max(2, titleDates.length)` или явная карта по `docType` из BSL (`СоответствиеТиповДокументовЭПД()`).
3. **Колонки:** вынести конфиг участников (`shipper`, `carrier`, `consignee`, …) в массив из метаданных/настроек, рендер `PartyCellView` в цикле.
4. **currentStep:** документировать все возможные значения из запроса списка (поиск по `ТекущийШаг` в `Module.bsl`).

## Связанные поля detail (для расширения)

- `waybillNumber` / `waybillDate` — из титула грузоотправителя (номер/дата накладной).
- `СоответствиеТиповДокументовЭПД()` — маппинг метаданных → коды ЭЗЗ, ЭТрН, ЭПЛ и др.
