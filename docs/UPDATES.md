# Обновление внешней обработки (.epf)

## Модель (v0.8.0)

1. Пользователь открывает обработку **из файла** (`bin\ПомощникДляЭДО.epf` или копия из `releases\…`).
2. Путь к файлу определяется автоматически: свойство платформы **`ИспользуемоеИмяФайла`** у объекта обработки (и параметр `ПутьКФайлуEpf` при открытии нового окна после обновления). Якорь нормализуется к `…\bin\ПомощникДляЭДО.epf`, путь сохраняется в хранилище общих настроек.
3. Рядом с якорем — **`releases\{version}\ПомощникДляЭДО.epf`** (+ `manifest.json`).
4. Проверка релизов — **на сервере 1С** (GitHub Releases API, asset `EdoAdiutor.epf`), без `fetch` в WebKit. Сразу после `ready` в React, **до** загрузки реестра ЭПД.
5. UI обновлений — **статус-бар**: бейдж версии (🔄 + зелёный перелив при новом релизе), всплывающее окно «Обновить / Остаться на текущей версии», клик по бейджу — повторная проверка и каталог версий (локальные + «скачать с GitHub»).
6. Сценарий обновления: скачивание в `releases\{version}` → подмена якоря → новое окно; старое — overlay «устарело».

Fallback манифеста: `ObjectModule.URLМанифестаОбновлений()` или `update-manifest.json` рядом с `.epf`.

## Сборка

```powershell
.\scripts\pack.ps1
# F7 в EDT, выгрузка bin\ПомощникДляЭДО.epf
# GitHub Release: asset EdoAdiutor.epf
```

## Ограничения

- Скачивание — HTTP(S) на **сервере** 1С; нужны права записи в каталог `.epf`.
- Если обработка встроена без файла на диске (`ИспользуемоеИмяФайла` пусто), локальные `releases` недоступны — остаётся только сценарий через URL/GitHub при известном якоре из настроек.
