# Автообновление файла .epf

## Как это работает

1. В `ObjectModule.bsl` задаётся `URLМанифестаОбновлений()` — ссылка на JSON в интернете или в локальной сети.
2. После старта React (action `ready`) и по кнопке «Проверить обновления» 1С загружает манифест по HTTP(S).
3. Если `version` в манифесте новее текущей `ВерсияПриложения()`, в интерфейсе показывается предложение обновиться.
4. Пользователь один раз указывает **файл .epf на диске**, который нужно перезаписывать (сохраняется в хранилище общих настроек).
5. По команде «Обновить файл .epf» 1С скачивает `epfUrl` из манифеста, делает резервную копию `*.bak` и заменяет файл. После этого нужно **закрыть и снова открыть** обработку из этого .epf.

## Формат манифеста

См. `bin/update-manifest.example.json`:

| Поле | Описание |
|------|----------|
| `version` | Версия сборки (semver `x.y.z`) |
| `epfUrl` | Прямая ссылка на файл .epf |
| `notes` | Текст для пользователя (необязательно) |

## Публикация

- Выложите актуальный `.epf` и `update.json` на HTTPS (или HTTP в LAN).
- Укажите URL манифеста в `URLМанифестаОбновлений()`.
- Сборка EPF: EDT → «Выгрузить в файл» или контур `ТестАвтосборкиEPF` (DESIGNER), если настроен XML-конвертер.

## Ограничения

- Замена файла выполняется на **клиенте** (нужны права записи в каталог .epf).
- Если обработка открыта не из файла, а из конфигурации/справочника доп. обработок, укажите путь к .epf вручную («Выбрать файл…»).
- Пустой `URLМанифестаОбновлений()` — проверка отключена.
